# 6. Quality of Service and Congestion Management

## 6.1 Network Congestion

### 6.1.1 Causes and Effects of Congestion

- Definition: congestion occurs when the aggregate demand for a network resource exceeds its available capacity
- Primary causes: bandwidth bottlenecks, traffic bursts exceeding link capacity, asymmetric link speeds between network segments
- Microbursts: short-duration traffic spikes that exceed buffer capacity even when average utilisation appears acceptable
- Effects on traffic: increased queuing delay, packet loss when buffers overflow, retransmission by TCP causing further load
- TCP congestion collapse: a condition in which retransmissions from multiple flows saturate a link, described by Van Jacobson in 1988
- UDP behaviour under congestion: no built-in backoff mechanism, meaning UDP flows can crowd out TCP flows
- Head-of-line blocking: a single large or delayed packet preventing subsequent packets from being processed
- Congestion in different network layers: Layer 2 (switch buffers), Layer 3 (router queues), and application layer (streaming buffers)
- Measurement indicators: interface utilisation, queue depth, packet drop counters, round-trip time increase

### 6.1.2 Buffer Management

- Role of buffers: absorbing short-term traffic bursts to prevent immediate packet loss
- Tail drop: the default behaviour in which packets are discarded once a queue is full, regardless of flow or priority
- Problems with tail drop: TCP global synchronisation, in which multiple flows simultaneously reduce their window size after experiencing loss, causing underutilisation followed by another burst
- Random Early Detection: a proactive queue management algorithm that begins dropping packets probabilistically before the queue is full, signalling congestion to TCP senders early
- Weighted Random Early Detection: extends RED by applying different drop thresholds to traffic classes, allowing higher-priority traffic to experience less early dropping
- Explicit Congestion Notification: a mechanism defined in RFC 3168 allowing routers to signal congestion to endpoints via IP and TCP header bits, avoiding packet loss as the signalling method
- Bufferbloat: the problem of excessively large buffers introducing high and variable latency without improving throughput; identified and named by Jim Gettys around 2010
- Active Queue Management algorithms addressing bufferbloat: CoDel and FQ-CoDel, which target latency rather than queue length as the control variable
- Buffer sizing trade-offs: small buffers reduce latency but increase drop rates under bursts; large buffers absorb bursts but increase queuing delay

## 6.2 Quality of Service

### 6.2.1 Traffic Prioritisation

- Definition: the practice of treating different traffic flows differently based on their characteristics or assigned class
- Rationale: not all traffic has the same latency, jitter, or loss tolerance; voice and video require low latency while bulk transfers can tolerate delay
- Classification: identifying traffic by source/destination IP, port, protocol, DSCP marking, or deep packet inspection
- Marking: assigning a class identifier to packets at ingress so that downstream devices can apply consistent treatment without re-classifying
- Trust boundaries: the point in the network where markings from end devices are accepted or overridden; typically at the access layer
- Queuing disciplines: how packets are scheduled for transmission once classified
  - First In First Out: no differentiation, default behaviour
  - Priority Queuing: strict priority between classes; risk of starvation for lower-priority queues
  - Weighted Fair Queuing: allocates bandwidth proportionally across flows
  - Class-Based Weighted Fair Queuing: applies weighted fair queuing to defined traffic classes rather than individual flows
  - Low Latency Queuing: combines strict priority for a defined queue with weighted fair queuing for remaining classes; commonly used for voice traffic
- Shaping vs. policing: shaping delays excess traffic to conform to a rate; policing drops or re-marks excess traffic immediately
- Congestion avoidance vs. congestion management: avoidance acts before queues fill; management acts on already-queued traffic

### 6.2.2 QoS Models

- Best Effort: the default internet model; no guarantees on delay, loss, or bandwidth; all packets treated equally
- Integrated Services: defined in RFC 1633; provides per-flow reservations using the Resource Reservation Protocol; guarantees bandwidth and delay for individual flows; does not scale to large networks due to per-flow state in every router
- Resource Reservation Protocol: a signalling protocol used by IntServ to request and maintain resource reservations along a path
- Differentiated Services: defined in RFC 2474 and RFC 2475; replaces per-flow state with per-class behaviour; routers apply a Per-Hop Behaviour based on the Differentiated Services Code Point field in the IP header
- DSCP values and standard Per-Hop Behaviours:
  - Default Forwarding: best effort
  - Expedited Forwarding: low latency, low loss, low jitter; intended for voice
  - Assured Forwarding: four classes with three drop precedences each; provides relative differentiation within a class
  - Class Selector: backward-compatible with the older IP Precedence field
- Comparison: IntServ offers hard guarantees but does not scale; DiffServ scales but provides only relative differentiation without hard per-flow guarantees
- End-to-end QoS: requires consistent policy across all network domains a packet traverses; difficult to enforce across administrative boundaries

### 6.2.3 MPLS

- Definition: Multiprotocol Label Switching, a forwarding mechanism in which packets are assigned a short fixed-length label at ingress and forwarded based on that label rather than an IP lookup at each hop
- Standardised by the IETF; core specifications in RFC 3031 (architecture) and RFC 3032 (label stack encoding)
- Label structure: 20-bit label value, 3-bit Traffic Class field, 1-bit bottom-of-stack indicator, 8-bit TTL
- Label Edge Router: the device at the boundary of an MPLS domain that imposes or removes labels
- Label Switch Router: a core device that forwards packets based solely on label lookup, without examining the IP header
- Label Distribution Protocol and RSVP-TE: two mechanisms for distributing label bindings between routers; RSVP-TE additionally supports traffic engineering with explicit path control
- Traffic engineering: MPLS allows operators to route flows along paths that differ from the shortest IGP path, enabling load balancing and bandwidth reservation across the network
- MPLS VPN: using label stacks to create isolated Layer 3 VPNs across a shared provider backbone; defined in RFC 4364
- MPLS and QoS: the Traffic Class field in the MPLS label carries a Per-Hop Behaviour equivalent, allowing DiffServ policies to be applied within an MPLS domain
- Relationship to VXLAN and SD-WAN: MPLS is a carrier-grade technology; enterprises increasingly replace private MPLS circuits with internet-based overlays, accepting different reliability and QoS trade-offs
- Decline in enterprise MPLS adoption: growth of broadband and SD-WAN has reduced demand for dedicated MPLS circuits, though MPLS remains in use within carrier backbones
