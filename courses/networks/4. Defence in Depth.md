# 4. Defence in Depth

## 4.1 Principles of Defence in Depth

### 4.1.1 Concept and Architecture

- Definition: layered security model assuming no single control is sufficient
- Historical origin: military concept adapted to information security
- Core assumption: attackers will breach outer layers; inner layers must limit damage
- The "concentric rings" model: perimeter, network, host, application, data
- Redundancy vs. diversity of controls: why using different technologies matters
- Trade-offs: complexity, cost, and operational overhead of multiple layers
- How layers interact: the importance of coherent architecture over stacking tools

### 4.1.2 Zero Trust

- Definition: "never trust, always verify" as a departure from perimeter-based models
- Historical context: coined by John Kindervag at Forrester Research (2010)
- Core principles: verify explicitly, use least-privilege access, assume breach
- Identity as the new perimeter: shift from network location to user/device identity
- Micro-segmentation: limiting lateral movement within the network
- Continuous authentication and authorisation vs. one-time login
- Relationship to Defence in Depth: complementary or alternative framing
- Implementation challenges: legacy systems, operational complexity, cultural resistance

## 4.2 Applied Cryptography

### 4.2.1 Encryption

- Symmetric vs. asymmetric encryption: definitions, use cases, performance trade-offs
- Common algorithms: AES, RSA, ECC and their respective key lengths
- Encryption at rest vs. encryption in transit: where each applies
- End-to-end encryption: definition and limitations
- Key management: generation, storage, rotation, and revocation
- Common weaknesses: weak keys, poor implementation, deprecated algorithms (DES, RC4)
- Regulatory requirements driving encryption adoption (GDPR, PCI-DSS)

### 4.2.2 Multi-Factor Authentication

- Definition: requiring two or more independent factors to authenticate
- Factor categories: knowledge, possession, inherence
- Common implementations: OTP, hardware tokens, authenticator apps, biometrics
- SMS-based OTP: convenience vs. known vulnerabilities (SIM swapping, SS7 attacks)
- Phishing-resistant factors: FIDO2/WebAuthn standard
- Adaptive authentication: adjusting requirements based on risk context
- Deployment considerations: user experience, fallback mechanisms, recovery procedures

### 4.2.3 Public Key Infrastructure

- Definition and components: certificate authority, registration authority, certificate revocation list, OCSP
- Certificate lifecycle: issuance, renewal, revocation
- Trust chains: root CA, intermediate CA, end-entity certificates
- X.509 standard: structure and fields
- Internal vs. public PKI: when each is appropriate
- Common failure modes: certificate expiry, mis-issuance, CA compromise
- Certificate Transparency logs as a monitoring mechanism

## 4.3 Firewall

### 4.3.1 Firewall Concepts and Types

- Definition: a system that filters traffic based on defined rules
- Packet filtering: stateless inspection based on headers (IP, port, protocol)
- Stateful inspection: tracking connection state to allow return traffic
- Application-layer firewalls: deep packet inspection, protocol awareness
- Next-generation firewalls: integrating IDS/IPS, application identification, user identity
- Web Application Firewalls: HTTP-specific filtering, OWASP rule sets
- Software vs. hardware vs. cloud-native firewalls
- Rule ordering and default-deny vs. default-allow policies

### 4.3.2 Firewall Placement in the Architecture

- Perimeter firewall: separating the internet from the internal network
- Internal segmentation firewalls: controlling east-west traffic
- Dual-homed and multi-homed configurations
- Relationship to DMZ architecture: what lives in the DMZ and why
- High-availability configurations: active-passive and active-active failover
- Asymmetric routing problems and how placement affects them
- Common misconfigurations: overly permissive rules, rule bloat, undocumented exceptions

### 4.3.3 OT Firewall

- Specific constraints of operational technology environments: legacy protocols, real-time requirements, limited patching
- Industrial protocols requiring specific handling: Modbus, DNP3, IEC 61850, OPC-UA
- Unidirectional security gateways (data diodes) as an alternative to bidirectional firewalls
- Air-gap vs. controlled connectivity: when each is appropriate
- Purdue model and IEC 62443 as reference architectures for OT segmentation
- Risks of IT/OT convergence and how firewall placement addresses them

## 4.4 Access Control Lists

### 4.4.1 How ACLs Work

- Definition: ordered lists of rules applied to network interfaces or file system objects
- Network ACLs: filtering based on source/destination IP, port, and protocol
- Standard vs. extended ACLs (Cisco terminology as a common reference)
- Stateless nature of ACLs: implications for return traffic
- Rule evaluation order: first-match logic and the implicit deny-all
- ACLs on routers vs. ACLs on switches (VACLs, PACLs)
- Operational challenges: rule sprawl, documentation, change management

### 4.4.2 Anti-Spoofing with ACLs

- IP spoofing: definition and threat model
- Ingress filtering: blocking packets with source addresses inconsistent with the incoming interface
- BCP38 (RFC 2827): the industry standard recommendation for ingress filtering
- Egress filtering: preventing spoofed packets from leaving the network
- Unicast Reverse Path Forwarding as a complementary mechanism
- Limitations: ineffective against spoofing within the same subnet or trusted network segment
- Relevance to DDoS amplification attacks: how anti-spoofing reduces participation

## 4.5 IDS and IPS

### 4.5.1 Intrusion Detection Systems

- Definition: passive monitoring systems that generate alerts without blocking traffic
- Network-based vs. host-based detection
- Signature-based detection: matching known attack patterns; limitations against zero-days
- Anomaly-based detection: baselining normal behaviour and flagging deviations
- False positive and false negative trade-offs: tuning implications
- Alert fatigue: operational consequences of poorly tuned systems
- Common open-source implementations: Snort, Suricata, OSSEC

### 4.5.2 Intrusion Prevention Systems

- Definition: inline systems that can block or modify traffic in real time
- Relationship to IDS: same detection logic, different enforcement position
- Inline placement: impact on latency and availability
- Fail-open vs. fail-closed behaviour during system failure
- Evasion techniques: fragmentation, encoding, protocol ambiguity
- Tuning requirements: why default rule sets are rarely sufficient out of the box
- Integration with firewalls and SIEM platforms

### 4.5.3 Multi-Layer Detection Strategies

- Why no single detection method is sufficient
- Combining network, host, and application-level detection
- Correlation of events across layers: the role of SIEM
- Deception technologies: honeypots and honeynets as complementary detection layers
- Threat intelligence feeds: enriching detection with external context
- Detection coverage mapping: using frameworks such as MITRE ATT&CK to identify gaps

## 4.6 Logging, Monitoring and Intrusion Detection

### 4.6.1 Logging

- What to log: authentication events, network flows, system calls, application errors
- Centralised log collection: syslog, syslog-ng, and structured logging formats (CEF, JSON)
- Log integrity: tamper-evident storage, write-once media, cryptographic chaining
- Retention policies: regulatory requirements vs. storage costs
- Log normalisation: making heterogeneous sources comparable
- Common gaps: devices that cannot log, high-volume sources that are filtered out, clock synchronisation issues

### 4.6.2 Security Operations Center

- Definition and function: centralised team responsible for monitoring, detection, and response
- Organisational models: in-house, outsourced, hybrid
- Core tooling: SIEM, SOAR, ticketing systems, threat intelligence platforms
- Tier structure: L1 triage, L2 investigation, L3 incident response and threat hunting
- Key metrics: mean time to detect, mean time to respond, false positive rate
- Staffing and shift coverage challenges
- Integration with incident response procedures and escalation paths

## 4.7 VPN

### 4.7.1 VPN Principles and Types

- Definition: encrypted tunnel over an untrusted network
- Site-to-site VPN: connecting two fixed networks
- Remote-access VPN: connecting individual users to a corporate network
- IPsec: tunnel vs. transport mode, IKE negotiation, ESP and AH protocols
- TLS-based VPNs: SSL VPN, OpenVPN, WireGuard
- Split tunnelling: definition, use cases, and security implications
- Performance considerations: encryption overhead, MTU issues

### 4.7.2 DMZ and VPN Architecture

- Definition of DMZ: a network segment exposed to untrusted networks while separated from the internal network
- Single-firewall DMZ vs. dual-firewall DMZ: trade-offs
- Where VPN concentrators are placed relative to the DMZ
- Traffic flows: what terminates in the DMZ vs. what passes through to internal networks
- Risks of placing VPN endpoints inside the internal network
- Combining VPN with Zero Trust: when VPN alone is insufficient

## 4.8 Authentication and Network Access Control

### 4.8.1 RADIUS

- Definition: Remote Authentication Dial-In User Service, a client-server protocol for centralised authentication
- Authentication, authorisation, and accounting functions
- How RADIUS integrates with network devices: NAS as a RADIUS client
- RADIUS vs. TACACS+: protocol differences and use-case fit
- EAP methods carried over RADIUS: EAP-TLS, PEAP, EAP-TTLS
- Known weaknesses: MD5-based attribute hiding, susceptibility to offline attacks
- RADIUS over TLS (RadSec) as a mitigation

### 4.8.2 Network Access Control

- Definition: enforcing policy on devices before or after they connect to the network
- Pre-admission vs. post-admission control
- Posture assessment: checking patch level, antivirus status, configuration compliance
- 802.1X as the standard mechanism for port-based access control
- Quarantine VLANs: isolating non-compliant devices
- Challenges with BYOD and IoT devices that cannot run 802.1X supplicants
- Integration with identity providers and endpoint management platforms

### 4.8.3 Read-Only Domain Controller

- Definition: a domain controller that holds a read-only copy of the Active Directory database
- Use case: deployment in physically insecure or remote locations
- Credential caching: which accounts are cached and the associated risks
- Filtered Attribute Set: preventing sensitive attributes from replicating to the read-only domain controller
- Administrator Role Separation: local administration without domain-wide privileges
- Attack surface reduction compared to a full domain controller

### 4.8.4 Bastion Host

- Definition: a hardened, publicly accessible host designed to provide controlled access to a private network
- Common uses: SSH jump host, RDP gateway, privileged access workstation
- Hardening requirements: minimal services, strict access control, comprehensive logging
- Relationship to Zero Trust: bastion hosts as a transitional architecture
- Risks: single point of failure for administrative access; compromise implications
- Modern alternatives: privileged access management platforms, just-in-time access

## 4.9 Traffic Matrix and Service Identification

### 4.9.1 Building a Traffic Matrix

- Definition: a structured mapping of expected communication flows between network segments or hosts
- Why it is needed: basis for firewall rules, ACLs, and anomaly detection baselines
- Data sources: network flow records (NetFlow, IPFIX), packet captures, application documentation
- Identifying authorised flows: involving application owners and system administrators
- Handling undocumented flows: discovery phase vs. enforcement phase
- Maintaining the matrix over time: change management integration
- Using the traffic matrix to validate firewall rule sets and detect rule bloat

## 4.10 Best Practices and Hardening

### 4.10.1 Oversizing and Backup

- Capacity planning: provisioning headroom to absorb traffic spikes and DDoS conditions
- Redundant links and devices: eliminating single points of failure
- Backup strategies: full, incremental, and differential backups
- Backup storage: on-site vs. off-site vs. cloud; air-gapped backups for ransomware resilience
- Recovery time objective and recovery point objective as design parameters
- Regular restoration testing: why untested backups cannot be assumed to work

### 4.10.2 Update Server

- Rationale: centralising patch distribution to avoid direct internet access from managed hosts
- Common implementations: WSUS for Windows environments, local mirrors for Linux package managers
- Controlling what gets approved and deployed: staged rollout and testing pipelines
- Risks of a compromised update server: supply chain implications
- Keeping the update server itself patched and hardened
- Offline update strategies for air-gapped or OT environments

### 4.10.3 Discretionary Access Control

- Definition: an access control model in which the resource owner determines access permissions
- Contrast with mandatory access control and role-based access control
- Implementation in common operating systems: UNIX permission bits, Windows DACL
- Principle of least privilege as the governing design rule
- Common misconfiguration patterns: overly permissive defaults, permission inheritance issues
- Auditing and reviewing permissions: tools and frequency
- Limitations: susceptibility to Trojan horse attacks, dependency on owner diligence
